# MoSCoW — Carro Robô 4WD

A técnica MoSCoW será utilizada para classificar as funcionalidades do projeto de acordo com sua prioridade.

## Must Have — Deve ter obrigatoriamente

São as funcionalidades essenciais para o funcionamento do MVP.

| Funcionalidade       | Descrição                                    |
| -------------------- | -------------------------------------------- |
| Chassi               | Estrutura para acomodar todos os componentes |
| 4 motores DC         | Um motor para cada roda                      |
| 4 rodas              | Permitir a movimentação do carro             |
| Bateria              | Alimentar os motores e a eletrônica          |
| Arduino Uno ou ESP32 | Controlar o funcionamento do robô            |
| Ponte H              | Controlar os motores                         |
| Avançar              | Movimento para frente                        |
| Recuar               | Movimento para trás                          |
| Virar à esquerda     | Movimento de direção                         |
| Virar à direita      | Movimento de direção                         |
| Parar                | Interromper o movimento                      |
| Teste dos motores    | Validar o funcionamento dos quatro motores   |

---

## Should Have — Deve ter, mas não é essencial para o MVP

São funcionalidades importantes para melhorar o produto final.

| Funcionalidade              | Descrição                                   |
| --------------------------- | ------------------------------------------- |
| Carenagem                   | Proteger os componentes                     |
| Carenagem removível         | Facilitar manutenção                        |
| Organização dos cabos       | Melhorar a montagem                         |
| Acesso à bateria            | Facilitar troca ou recarga                  |
| Interruptor                 | Ligar e desligar o sistema                  |
| Teste térmico               | Verificar temperatura dos motores e drivers |
| Melhor distribuição de peso | Melhorar estabilidade                       |

---

## Could Have — Poderia ter

São funcionalidades interessantes, mas que não são necessárias para a conclusão do MVP.

| Funcionalidade           | Descrição                        |
| ------------------------ | -------------------------------- |
| Sensor ultrassônico      | Detectar obstáculos              |
| LEDs                     | Sinalização visual               |
| Buzzer                   | Sinalização sonora               |
| Controle Bluetooth       | Controlar o carrinho sem fio     |
| Controle por aplicativo  | Controlar através de celular     |
| Modo autônomo            | Movimentação utilizando sensores |
| Monitoramento da bateria | Verificar o nível de carga       |

---

## Won't Have — Não terá nesta versão

Estas funcionalidades não fazem parte do escopo atual do projeto.

| Funcionalidade          | Motivo                                         |
| ----------------------- | ---------------------------------------------- |
| RFID                    | Não é necessário para o funcionamento do carro |
| GPS                     | Não faz parte do objetivo atual                |
| Câmera                  | Aumenta a complexidade do projeto              |
| Visão computacional     | Fora do escopo atual                           |
| Inteligência Artificial | Não é necessária para o MVP                    |
| Navegação avançada      | Poderá ser implementada futuramente            |
